1. **무엇이 위험했는지**


    기존 코드에서는 API 키와 DB_URL이 코드에 그대로 하드코딩되어 있었고, 접속 시도 로그와 요청 헤더 디버그 출력에도 비밀번호와 API키 전체가 포함되어 출력되는 문제가 있었다. 이런 코드는 커밋하는 순간 git 내역에 영원히 남고 코드를 공유하거나 로그 파일을 보는 사람들에게 키값이 노출되는 점이 위험했다.

2. **어떻게 고쳤는지**
    
    위의 문제를 해결하기 위해 노출되면 안되는 키값과 비밀번호를 .env 파일로 분리하고 python-dotenv()와 os.getenv()로 읽어 오도록 코드를 수정했다. 또한 .gitignore에 .env파일을 등록하여 커밋했을 때 저장소에 올라가지 않게 했다.

3. **만약 실키가 1차 커밋으로 노출되었다면 올바른 대응 절차는 무엇인지**
    
    만약 키가 노출된다면 가장 먼저 해당 키를 즉시 폐기하고 새 키를 재발급받는다. 그후 새 키는 .env로 격리하고 .gitignore를 정비한다. 사용량,청구 내역을 점검하고 필요시 사업자에 신고한다. 히스토리에 남은 옛 키는 이미 무효이므로 위협이 아니지만 , 저장소 정리가 필요하면 이력 재작성 도구를 쓴다.
